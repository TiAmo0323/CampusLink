# 需求与设计修订基线（2026-09-05）

以正式版2的第1—2.3节和原大纲的第2.4—2.5节为基础。原附件保留；后续章节修订版 Word/PDF 由 scripts/revise_requirements.py 生成，替代旧大纲2.4—2.5并增加2.6统一规则，不重新引入旧大纲前半部分。本文明确本次修订决策，不把实现尚未验证的内容写成已验收。

## 统一规则

- 第一版部署为 Vue/Nginx、Java/Spring Boot、MySQL 三服务。Redis、短信不是必需依赖。公开任务列表、详情、启用技能字典允许匿名读取；其余业务接口必须鉴权。
- 注册使用用户名、密码、昵称和至少一种校园身份；第一版校验格式与唯一性，不宣称完成学校实名核验。注册返回登录凭证并进入首页；TC-01 与此一致。
- 标准 HS256 JWT 有效期2小时，刷新凭证7天、每次轮换、数据库仅保存哈希；退出和封禁撤销刷新会话。每个受保护请求重新校验账户状态和凭证版本，封禁后旧访问令牌立即失效，解封不恢复旧令牌。连续5次错误密码锁定10分钟，正确登录清零。无需 Redis。
- 任务与订单统一状态：RECRUITING（仅任务）、WAIT_EXECUTE、IN_PROGRESS、WAIT_ACCEPTANCE、COMPLETED、CANCELLED、ABNORMAL。DRAFT 仅为前端未提交草稿，不落库。完成记录状态为 PENDING/APPROVED/REJECTED。
- 招募中发布者取消：返还积分、不扣信用。待执行任一方取消：必须说明原因，取消发起人扣5信用，另一方不扣分；双方收到通知。进行中/待验收只能申诉。取消原因保存在任务中。
- 待处理申请可以撤回；撤回不删记录，不允许重复申请同一任务。我的任务提供已申请、已接取、已发布分页入口。
- 验收驳回默认累计3次（按当前履约轮次计数）进入 ABNORMAL，原因 REJECT_LIMIT，交由管理员处理；不自动扣信用。
- TIMEOUT/REJECT_LIMIT 异常允许发布者从原未选中的有效账户申请者重新选择；争议异常必须由管理员裁决。复用原订单ID，增加履约轮次；保存原接取者、原时间、重新分配原因及新接取者。完成记录保存提交人和轮次。重新分配必须给出新的未来完成期限，清空当前轮次开始/完成时间；原凭证、流水、信用、处理记录保留。原接取者可以查看自己历史提交，不可操作新轮次。
- 任务预计时长保存为 estimated_duration_minutes（默认60分钟）；技能可用时间保存 available_time；最近登录保存 last_login_at。约定完成期限优先取申请预计完成时间，否则为任务时间加预计时长；系统超时宽限可配置，默认0小时。
- 技能互助发起即创建 PENDING；接受更新 ACCEPTED；发起者开始；提供方先标记完成、发起者随后确认才 COMPLETED。保存 provider_completed_at；ACCEPTED/IN_PROGRESS 任一方可取消，不涉及任务奖励账本。
- 匹配按技能覆盖率50%、信用20%、平均星级/5占20%、近30日完成数/10占10%计算，单项上限1，无评价0.6。按最终分数降序，同分双向互补优先，再按用户ID；不把互补置于分数之前。默认首屏10条，可分页，每页最多50条。
- 信用分值为履约+5、高评+2、低评-3、无故取消-5、超时-2、核实违规-10。实际 change_value=after_score-before_score，达到0/100边界时允许0变化事件以保留原因，禁止 change_value<>0 约束。
- 积分流水同时保存可用及冻结余额前后值，change_amount表示可用余额变化，结算发布者可为0，但冻结余额必须反映扣减；禁止 change_amount<>0 约束。旧流水无法可靠还原的冻结前后值为NULL，不能伪造历史。
- 申诉统一 report.target_type=ORDER，保存 previous_status；普通举报保留 USER/TASK/SKILL/REVIEW。举报状态 PENDING/PROCESSING/RESOLVED。管理员下架用独立 is_delisted 标记，不等同直接取消履约或删除历史。
- 所有面向用户的集合查询默认10条、最大50条；资料聚合中的子列表也分页。字典通过分页逐批加载；不以截断伪装分页。任务列表批量读取发布者、匹配批量获取/聚合候选信息，避免 N+1。
- 性能验收：10万任务，50并发查询，p95≤1秒、成功率≥99%；写操作p95≤2秒；1000候选匹配p95≤1秒。必须报告数据量、环境、持续时间与结果，不能用功能测试替代 MySQL/JMeter 验收。
- UI-M01—UI-M08、UI-P01、UI-R01 保留；移动端包括个人资料、申请撤回、举报、异常处理、凭证上传与双端验收。无需另建原生前端。

## 开发与验收目标

1. 登录安全与令牌刷新、撤销、锁定测试。
2. 个人中心与我的申请入口。
3. 普通举报、管理领取/处理、下架、账户封禁。
4. 申请撤回、分阶段取消、驳回上限、超时与重新分配审计。
5. 完整分页、批量查询、可复现压测及真实结果记录。
6. UI-M01—UI-M08 全链路移动端验证。
7. 统一状态枚举和三服务部署文档，不新增 Redis。
