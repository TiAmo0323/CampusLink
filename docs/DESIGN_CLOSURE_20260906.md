# CampusLink 文档符合性收口与测试准入报告（2026-09-06）

## 1. 结论

本轮继续以《CampusLink需求分析与详细设计书_正式版2》第 1—2.3 节为前半基线，以《后续章节修订版》第 2.4 节以后及 2.6 统一规则为后半基线。当前项目已达到**进入正式系统测试/验收测试**的工程条件；核心功能、接口、MySQL 迁移、并发事务、响应式页面和文档规定的性能接口均已有自动化通过证据。

仍不能表述为“逐字逐类、逐像素 100% 严格一致”：设计书列举的细粒度 Controller/Service 资源在实现中有合并；部分复杂 VO 在控制器边界有命名类型，但内部仍由 Map 组装；尚未完成真机人工体验、逐像素原型验收和生产环境安全/容量审计。这些不阻止进入测试阶段，但阻止直接宣告最终生产验收完成。

## 4. 测试阶段准入与退出要求

当前可进入正式系统测试。测试应固定 Git 提交/版本号、测试数据库快照、后端包、前端构建和 APK 哈希；不得把测试连接到业务库。

建议按以下方法执行：

1. 接口与业务回归：在 H2 快速回归后，以 MySQL 8 空库执行 Flyway V1—V6，再运行全部 MockMvc/集成用例；检查统一响应、权限、分页总数和状态转换。
2. 事务与并发：并发执行选择接取者、刷新令牌、任务发布、验收结算和超时处理；核对订单唯一性、积分/冻结余额、流水、信用记录及回滚。
3. 安全测试：覆盖越权、过期/篡改/重放令牌、登录锁定、参数边界、伪造文件、超限文件、外部/不存在上传地址；生产上线前另做恶意文件扫描与依赖漏洞扫描。
4. UI/兼容性：用 Playwright 在 360/390/412/1920 视口跑完整业务链；人工检查 Chrome/Edge 和至少一台 Android WebView/真机的键盘遮挡、文件选择、图片/PDF查看与弱网提示。
5. 性能：在独立 MySQL 上保留不少于 10 万任务和 1000 候选，JMeter 复跑七类接口；查询 P95≤1 秒、写入 P95≤2 秒、成功率≥99%，并检查死锁和连接池耗尽。
6. 验收退出：P0/P1 缺陷为 0，P2 有书面处置；22 项后端、8 项端到端、Web/Android/Compose 构建及性能门槛全部复现通过；保存 JTL、日志、环境和源码/制品哈希。

## 5. 剩余差距与边界

- 设计书列举了更细粒度的 `TaskApplicationController`、`TaskOrderService` 等资源；当前实现按业务域合并，但依赖方向已符合分层原则。若学校按“类名逐项核对”评分，仍需做纯结构拆分。
- `LoginVO`、`TaskDetailVO`、`DashboardVO` 等复杂对象在 Controller 边界已有命名 VO，但内部仍使用受保护的 Map 组装；若要求字段级编译期契约，应继续改成完整 record/class 投影。
- 浏览器 Device Mode 已达到文档最低移动验收要求；本轮 APK 已更新并编译，但未在真实 Android 设备完成整链人工验收。
- Element Plus 与管理台分包仍有超过 500 kB 的构建警告；不影响正确性准入，但属于首屏性能优化项。
- 当前工作树包含大量尚未提交的项目既有改动和文档产物。正式测试前应由项目负责人审阅后形成不可变提交/标签，否则缺陷与证据难以精确追溯。
