# CampusLink 第二轮整改与验证记录

日期：2026-09-05

基线：2.3 节及之前采用《CampusLink需求分析与详细设计书_正式版2》，2.3 节之后采用《CampusLink需求分析与详细设计书_后续章节修订版》。本记录对应 `DESIGN_REAUDIT_20260905.md` 的 R01—R13。

## 整改结果

| 项目 | 结果 |
|---|---|
| R01—R02 查询规模 | 任务卡片、申请者、我的任务和技能互助列表改为分页后批量装配；申请者技能与评价提供独立分页接口，删除当前页内逐条查询。 |
| R03 过期招募 | 公共招募列表强制 `application_deadline > now`，并增加回归用例。 |
| R04 并发状态 | 超时任务的订单和任务更新均检查受影响行数；任一步不为 1 即回滚。性能复测进一步发现并修复并发登录清理刷新会话造成的 MySQL 死锁。 |
| R05 性能证据 | 新增 `scripts/verify_performance_current.py`，在 10 万任务、1000 候选的 MySQL 8 隔离库覆盖任务列表/详情、匹配、申请列表、开始、完成提交和结算，并保存源码 SHA-256。 |
| R06 数据表 | 删除设计外的 `governance_action` 实体、Mapper 和建表语句；治理动作、实际责任用户及说明写入既有 `report.handle_result`。最终业务表为 16 张。 |
| R07 状态定义 | 任务、申请、完成记录、互助、举报、账户、角色和技能状态统一使用 `States`。 |
| R08 接口响应 | 完成提交接口返回 `TaskCompletion`；技能供给/需求兼容路径返回更新后的用户信息。 |
| R09 分页 | 管理台、钱包、消息和评价列表默认 10、最大 50；申请者技能/评价、技能页收到的评价均可翻页。 |
| R10 任务界面 | 增加任务状态筛选；发布表单增加必填、未来时间、截止先于任务时间、奖励不超过可用积分校验；详情与履约页增加移动固定操作区；履约改为五步；上传显示文件列表。 |
| R11 钱包、匹配、管理界面 | 钱包改为积分、信用、收到评价三页签并显示信用等级；匹配保留分值、理由和互补标识；管理台改为四卡、两图、人工待办表。 |
| R12 管理聚合 | 任务分类分布改为数据库 `GROUP BY category`，不再读取全部任务实体。 |
| R13 举报证据 | 管理弹窗展示用户、任务、技能、评价对象详情；处理结果记录实际 `USER#id`，可从举报记录追溯责任用户。 |

## 最终验证

- H2：`mvn clean test -q`，21/21 通过。
- MySQL 8：从空库执行 V1—V6 后运行同一套测试，21/21 通过。
- 数据模型：V1—V6 的 `success` 均为 1；排除 Flyway 历史表后业务表数量为 16。
- 前端：`npm.cmd run build` 通过。
- 浏览器：`npx.cmd playwright test`，8/8 通过，覆盖任务发布、申请、接取、开始、凭证上传、驳回、重提、验收、技能互助及 360/390/412/1920 像素无横向溢出。
- 性能：七组均为 0 失败。10 万任务、50 并发、500 次列表请求 p95 261.78 ms；任务详情 p95 88.84 ms；1000 候选匹配 p95 123.56 ms；申请列表 p95 59.36 ms；开始/完成提交/结算 p95 分别为 87.07/73.96/555.13 ms。
- 完整性能数据与源码哈希见 `verification-20260905/performance-current.json`。

## 迁移说明

V6 现在只增加查询索引和账本检查约束，不创建第 17 张业务表。该迁移尚未成为仓库正式发布基线；部署到已经执行过早期试验版 V6 的数据库前，需要按实际部署记录制定新的修正迁移，不能直接改写已发布迁移的校验和。
